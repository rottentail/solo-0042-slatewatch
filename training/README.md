# Slatewatch 盲标练习实验室（培训组 / 复盘专用）

这套材料回答一个考核问题：**审片员会不会因为两条音轨“流名相同”，就把同名参考轨当成主混？**
它不是考学员能否猜出出题人用了哪个文件。盲标阶段，学员只拿到短段画面、两条等长试听
（甲 / 乙）和一份写明“哪个画面动作应与哪些现场声同步”的制作记录；**真实流号、相同流名
的具体标签和真实覆盖全部扣留到复盘**。

设计与仓库的 Slatewatch 技审台一致：母带是**可复跑的双音轨 Matroska**，覆盖 / 静音真值由
**真实 Slatewatch 扫描**和一个只信字节的独立探测器共同重算，并带反泄漏核查。

---

## 1. 一分钟使用

```sh
# 仓库根目录，准备与 README 相同的环境（已验证 Python 3.12 + av 19.0.2）
uv venv --python 3.12 .venv && uv pip install --python .venv/bin/python -r requirements.txt

.venv/bin/python training/build_blind_lab.py   # 可复跑：母带 + 盲包 + 答案底册
.venv/bin/python training/verify_truth.py       # 独立重算 + 真实扫描配对 + 反泄漏核查
```

- **直接发放**：把 `blind_pack/Slatewatch盲标练习_盲包.zip` 发给学员（或整个 `blind_pack/`
  目录）。解压后双击 `Slatewatch-blind-lab/index.html`（zip 内已含顶层目录），媒体全部内嵌，
  可离线使用；也可分发 `assets/` 散文件供剪辑 / 音频工具核对。
- **复盘主持**：保留 `debrief/`（答案、母带、真值、扫描配对、核查报告），**不要**发出去。
- `verify_truth.py` 退出码为 0 才表示全部关键核查（当前 188 项）通过；任何真值 / 盲包被改动都会非 0 并列出失败项。

> 仅独立重算观测（不做泄漏审计）：
> `.venv/bin/python training/recompute_truth.py` → `debrief/recomputed_truth.json`。

## 3. 题目结构（主持须知，盲包内不标可辨 / 不可辨）

盲包用中性编号 `BL-01…BL-06` 并**交错**排列，学员不会看到“A 组可辨、B 组不可辨”的标签。

| 盲号 | 内部 code | 类型 | 盲材表现 | 正确结论 |
| --- | --- | --- | --- | --- |
| BL-01 | A1 | 声画辨轨 | 乙的打点与白闪 / 制作记录一一对应；甲保留首点、后两点漂移 | **乙 = 主混（甲为换错 / 参考轨）** |
| BL-02 | B1 | 必须存疑 | 甲、乙 WAV **字节完全相同**且都同步；差异只剩被扣留的流号 / 覆盖 | **无法确认** |
| BL-03 | A2 | 声画辨轨 | 甲对齐；乙首点对齐、后两点提前 | **甲 = 主混** |
| BL-04 | B2 | 必须存疑 | 甲、乙字节完全相同；流号与交叉覆盖不同但被扣留 | **无法确认** |
| BL-05 | A3 | 声画辨轨 | 乙对齐；甲首点同、后两点分别延后 / 提前 | **乙 = 主混** |
| BL-06 | A4 | 声画辨轨 | 甲对齐；乙首点同、后两点错位 | **甲 = 主混** |

声画组答案甲 / 乙 = 2 / 2，主混物理流号 index 1 / 2 = 2 / 2，且盲标签与物理流号无固定共现。

### 交叉的“相同静音外观”

每个 6.40 s 母带都有两段 **0.80 s 全零平台**：

- `L1 = 1.60–2.40 s`，`L2 = 3.20–4.00 s`。

两条物理音轨、甲 / 乙盲 WAV 在这两处都是逐采样全零，波形 / 听感完全一样；但真值交叉：
对同一条流，一个平台是**有覆盖的实录数字静音**（扫描出 `silence`），另一个是**整块不 mux
音频帧形成的无覆盖空洞**（PTS 跳变，扫描出 `sound_gap`，盲试听按完整时长补零）。主混与参考轨
的空洞平台互换。因此“看见全零 / 听见安静”既不能判断覆盖，也不能用来选轨。

### 为什么四类“捷径”都不能泄底

`leak_audit.md` 有逐项矩阵：

1. **谁先播放 / 固定选第一个**：练习页不自动播放；声画组答案甲乙各半，总选甲只有 2/4。
2. **哪条开头对齐**：甲、乙起点采样都为 0、前导零样本数相同，且**第一个打点在两条里刻意完全一致**；
   只有继续核对第 2、3 个动作才能分辨（防止只看开头）。
3. **波形全零**：两条都有位置 / 长度逐点相同的两个全零平台；没有任何一条是全零文件。
4. **文件长度**：所有 WAV 同为 16 kHz 单声道 102400 采样，字节数全部相同（204844 B）；
   画面同为 160 帧 / 6.40 s。

此外盲包文本不含母带 SHA、真实流名标签（两条物理流的 `title` 都写成同一个
`主混 MIX`，但该字面量不进盲包）、流号映射或答案键；内嵌 JSON 只允许媒体 / 时序字段。

## 4. 现场流程建议

1. 发 zip、答题卡，独立作答（约 12–18 分钟）。可统一说：“证据不足时写无法确认，不猜流号 / 文件。”
2. 复盘先统计 A 组被“同名 / 默认第一条 / 开头对齐”带偏的比例。
3. 用 `index.html` 复看 A 组：只盯白闪与打点，证明多点对齐能识轨。
4. B 组现场比较 `assets/BL-02|BL-04/jia.wav` 与 `yi.wav` 的 SHA-256（完全相同），
   说明盲材内不存在可判定函数，“无法确认”才对。
5. 打开 `debrief/复盘手册-答案与真值.md` 公布流号与相同流名；用 `scan_pairing.json` /
   `verification_report.md` 展示真实覆盖，指出同样全零外观下 `silence` 与 `sound_gap` 之别。
6. 宣读 `debrief/leak_audit.md`，说明四类提示经核查均不泄底。

### 两种发放模式

- **双盲对比（默认）**：每题给甲 / 乙，适合训练声画比对。
- **单盲贴标**：若要更贴近“只拿到一条试听，判断它是不是主混 / 是否换错”，主持可只发
  `jia.wav` 或 `yi.wav` 之一（配合 `picture.mp4` 与记录）。该候选对应主混还是参考，查
  `truth.json` 的 `blind_to_role`；A 组中拿到错轨的学员应判“不同步 / 换错轨”，B 组无论拿到
  哪条都只能判“无法确认流身份”。注意单盲发放物要重新剔除另一条 WAV，避免甲 / 乙同时泄露对比答案。

### 在 Slatewatch 工作台里复核母带（可选）

```sh
.venv/bin/python -m slatewatch.http --root ./slatewatch-vault
# 登记 debrief/masters/BL-01_A1_dual.mkv 时，用 sound=1 或 sound=2 分别选轨扫描；
# 同一母带选不同音轨会得到不同覆盖 / 候选，这正是本题的系统级注脚。
```

`verify_truth.py` 已通过 `Slatewatch` 服务入口在临时保管库里对每条音轨做了等价的真实扫描配对，
无需手动起服务。

## 5. 可复跑性与边界

- 采样、画格、时点、流号分配全部由 `lab/model.py` 的固定设计决定，**无随机数**；重跑构建会得到
  语义相同的信号。Matroska 容器字节 / 派生 ID 可能随 mux 时间戳微变，因此核查比对的是解码后的
  采样、覆盖区间、起振与白闪，并重新计算 SHA 写入新的 `truth.json`，不要求容器字节逐位复现。
- `probe.py` 是**独立**实现：直接用 PyAV 解母带 / WAV / PNG，用自带的采样与像素统计重算，
  不调用 `builder` 的判定函数。它与真实 `slatewatch.service` 扫描结果交叉一致。
- 若你调整 `model.py`（改时点 / 数量 / 映射），依次重跑 `build` 与 `verify`；核查会强制新设计满足
  “甲乙等长同形、首点一致、答案平衡、交叉静音、B 组字节相同、盲包无泄漏”等不变量，否则非 0 退出。
